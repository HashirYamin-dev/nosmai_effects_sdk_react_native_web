# Expo SDK 54 integration

This Nosmai compatibility line targets React Native 0.81.5, React 19.1, and New
Architecture. These versions align with Expo SDK 54. The package contains
custom Android and iOS code, so it does not run in Expo Go; create a development
or production build instead.

## 1. Align the Expo application

After upgrading the host application, let Expo align its dependency versions:

```sh
npx expo install --fix
npx expo-doctor
```

Do not widen or override Nosmai's React Native peer range to hide another
package's conflict. Update or replace the incompatible package instead.

## 2. Supply the Android SDK privately

The npm package intentionally excludes the proprietary Android AAR. For a local
build, place the authorized artifact outside generated native directories:

```text
vendor/nosmai-release.aar
```

Do not use `android/app/libs` as the source. Expo deletes the generated
`android/` directory during a clean prebuild. The config plugin copies the AAR
to the exact generated location needed by the React Native wrapper.

For EAS, `androidAarPath` may be an absolute path supplied by an EAS file
environment variable. The plugin also reads `NOSMAI_ANDROID_AAR_PATH` and the
optional `NOSMAI_ANDROID_AAR_SHA256` environment variable. Never place an AAR
or license key in a public repository, npm archive, log, or analytics payload.

## 3. Configure the plugin

Use dynamic app configuration when an environment variable supplies the AAR:

```js
// app.config.js
export default {
  expo: {
    plugins: [
      [
        '@nosmai/react-native-effects-sdk',
        {
          androidAarPath:
            process.env.NOSMAI_ANDROID_AAR_PATH ??
            './vendor/nosmai-release.aar',
          androidAarSha256: process.env.NOSMAI_ANDROID_AAR_SHA256,
          cameraPermission:
            'Allow this app to use the camera for Nosmai effects.',
          microphonePermission:
            'Allow this app to use the microphone when recording video.',
          photoLibraryAddPermission:
            'Allow this app to save captured photos and videos.',
        },
      ],
    ],
  },
};
```

If the app also uses `expo-build-properties`, list the Nosmai plugin after it so
the required ARM64 architecture value is the final generated value.

All permission-text options are optional. An explicit option replaces the
matching iOS value; otherwise an existing host value is preserved; otherwise a
safe default is added.

The Android plugin work is intentionally limited to configuration that cannot
come from library autolinking:

- Copies and optionally verifies the authorized AAR.
- Adds the app-level AAR runtime dependency exactly once.
- Sets `reactNativeArchitectures=arm64-v8a` because the native SDK is ARM64-only.
- Keeps `newArchEnabled=true`, which is required by the TurboModule/Fabric API.

Camera, internet, microphone, and legacy API 28 storage declarations already
merge from the library manifest. Runtime camera and microphone permission
prompts remain the host application's responsibility.

iOS autolinking uses the package podspec and installs `NosmaiCameraSDK ~> 3.0.4`.
The config plugin does not modify the Podfile or force `use_frameworks!`.

## 4. Generate and rebuild native applications

```sh
npx expo install expo-dev-client
npx expo prebuild --clean
npx expo run:android
npx expo run:ios --device
```

Installing the JavaScript package or restarting Metro is not enough. Rebuild
the development client whenever Nosmai native code or configuration changes.

Before using `--clean`, commit or back up unrelated manual native changes. When
`android/` and `ios/` are committed instead of generated by CNG, run prebuild
and commit the resulting native configuration.

## Platform limits

- Android requires an ARM64 physical device; x86/x64 emulators are unsupported.
- The current iOS native framework is device-only; use a physical arm64 iPhone.
- License keys remain separate app-bound runtime values. The Expo plugin does
  not accept or persist them.
- The plugin configures Nosmai only. It cannot repair unrelated third-party
  libraries that do not support Expo SDK 54, React Native 0.81, or New
  Architecture.

## Common failures

### Android AAR was not found

Set `androidAarPath` to an existing `.aar`, or set
`NOSMAI_ANDROID_AAR_PATH`. Keep the source outside the generated `android/`
directory.

### SHA-256 verification failed

The supplied artifact does not match `androidAarSha256` or
`NOSMAI_ANDROID_AAR_SHA256`. Obtain the authorized artifact/checksum again; do
not bypass the check by editing generated Gradle files.

### Native module is missing

The app is running in Expo Go or in an old development client. Generate and
install a new development build containing the Nosmai native module.

### Another dependency fails on SDK 54

Run `npx expo install --fix` and `npx expo-doctor`, then update or replace that
dependency with a React Native 0.81/New-Architecture-compatible release. The
Nosmai package's supported peer range is intentionally not widened without
native qualification.
